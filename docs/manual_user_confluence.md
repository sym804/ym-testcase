# YM TestCase 사용자 매뉴얼

> **최종 업데이트**: 2026-03-18
> **버전**: 0.4.0.0
> **대상**: 전체 사용자

---

## 1. 개요

**YM TestCase**는 테스트 케이스(TC)의 관리, 테스트 수행, 결과 분석 및 리포트 생성을 위한 웹 기반 테스트 관리 시스템입니다.

**주요 기능:**
- 프로젝트 단위 테스트 케이스 관리 (CRUD, Excel Import/Export)
- 테스트 수행 및 결과 기록 (키보드 단축키, 첨부파일 지원)
- 테스트 런 간 비교 (변경/리그레션 감지)
- 대시보드 (도넛 차트, 바 차트, 히트맵 등 분석)
- 리포트 생성 (PDF / Excel 다운로드)
- 역할 기반 접근 제어 (Admin, QA Manager, User)
- 비밀번호 정책 관리 (최소 8자, 강제 변경)

## 2. 로그인 / 회원가입

### 2-1. 로그인

> 📎 `01_login_page.png`

1. 아이디(사용자명)를 입력합니다.
2. 비밀번호를 입력합니다.
3. **로그인** 버튼을 클릭합니다.
4. 성공 시 프로젝트 목록 페이지로 이동합니다.

💡 **TIP**: 로그인 실패 시 5분간 최대 10회까지 시도할 수 있습니다. 초과 시 일시적으로 잠깁니다.

### 2-2. 회원가입

> 📎 `02_register_page.png`

1. 로그인 화면 하단의 **"회원가입"** 링크를 클릭합니다.
2. 아이디, 표시명, 비밀번호를 입력합니다.
3. **회원가입** 버튼을 클릭합니다.

⚠️ **비밀번호 규칙**: 비밀번호는 **최소 8자** 이상이어야 합니다.

⚠️ **참고**: 최초 가입 사용자는 자동으로 **Admin** 역할이 부여됩니다. 이후 가입자는 **User** 역할로 시작하며, 관리자에게 역할 변경을 요청해야 합니다.

### 2-3. 비밀번호 변경

1. 로그인 후 사용자 정보 영역에서 **비밀번호 변경**을 선택합니다.
2. 현재 비밀번호를 입력합니다.
3. 새 비밀번호를 입력합니다 (최소 8자).
4. **변경** 버튼을 클릭합니다.

⚠️ **강제 변경**: 관리자가 비밀번호를 초기화한 경우, 다음 로그인 시 비밀번호 변경이 강제됩니다. 변경 완료 전까지 다른 기능을 사용할 수 없습니다.

💡 **TIP**: 새 비밀번호는 현재 비밀번호와 동일할 수 없습니다.

### 2-4. 사용자명 중복 확인

회원가입 시 아이디를 입력하면 실시간으로 사용 가능 여부가 표시됩니다. 이미 등록된 아이디는 사용할 수 없습니다.

### 4-1. API 키

스크립트나 CI 에서 비밀번호 대신 사용하는 키입니다. 요청 헤더에 `Authorization: Bearer ymtc_...` 형식으로 전달합니다.

1. 사용자 메뉴에서 **API 키** 를 선택하고, 이름과 만료(30 · 90 · 180 · 365일 또는 없음, 기본 90일)를 정해 **발급** 을 누릅니다.
2. 발급된 키는 그 자리에서 한 번만 표시됩니다. **복사** 버튼으로 복사해 안전한 곳에 보관합니다. 서버에는 해시만 저장되어 다시 확인할 수 없습니다.
3. 목록에서 이름 · 키 앞부분 · 만든 날 · 마지막 사용 · 만료일 · 상태를 확인하고, 사용하지 않는 키는 **폐기** 합니다. 폐기한 키를 사용하는 스크립트는 바로 막힙니다.

- 키의 권한은 내 계정과 같습니다. 다만 키로는 키 관리 · 비밀번호 변경 · 로그아웃을 할 수 없고, 관리자 키로도 비밀번호 초기화와 계정 복구 승인을 할 수 없습니다.
- 한 사람이 동시에 사용할 수 있는 키는 20개까지입니다.

⚠️ **주의**: 비밀번호가 바뀌면(본인 변경 · 관리자 초기화 · 계정 복구) 그 계정의 API 키가 모두 폐기됩니다. 스크립트에는 새 키를 발급해 넣어야 합니다.

### 6-4. 폴더 / 시트 이름 변경

- 왼쪽 시트 트리에서 폴더/시트 행의 **✎** 버튼을 누르거나 이름을 더블클릭하면 이름이 입력칸으로 바뀝니다.
- **Enter** 나 입력칸 밖 클릭은 저장, **Esc** 는 취소입니다. 이름을 그대로 두면 아무것도 바뀌지 않습니다.
- 시트 이름을 바꾸면 그 시트의 TC 와, 그 시트를 범위로 고른 테스트 수행도 새 이름을 따라갑니다.
- 같은 이름의 시트가 있거나 TC 번호가 겹치면 저장되지 않고 사유가 표시됩니다.
- 이름 변경은 프로젝트 Admin 만 할 수 있습니다.

## 7. 테스트 수행

> 📎 `09_testrun_tab.png`

### 7-1. 테스트 런 생성

1. 좌측 패널 하단의 **"+ New Test Run"** 버튼을 클릭합니다.
2. 런 이름, 라운드(R1/R2/...), 버전, 환경을 입력합니다.
3. 생성 시 프로젝트의 모든 TC가 **NS(미실행)** 상태로 포함됩니다.

### 7-2. 테스트 런 목록

- 좌측 패널은 **버전 → 수행 이름 → 회차** 세 단계 트리입니다. 버전은 앞의 v 와 대소문자를 무시해 묶고, 같은 이름의 수행은 회차별로 한 묶음이 됩니다.
- 버전과 수행 이름은 펼치고 접습니다. 진행 중인 수행이 없는 버전은 처음부터 접혀 건수만 보입니다.
- 회차 행에 환경 · 상태(진행 중/완료) · 진행률이 표시됩니다. 이름을 클릭하면 최근 회차가, 회차 행을 클릭하면 그 회차가 우측에 열립니다.
- 목록 위에서 이름 검색, 상태 · 환경 필터를 걸 수 있습니다(환경은 대소문자 무시).

### 7-3. 결과 입력

| 방법 | 설명 |
|---|---|
| 🖱️ 마우스 | 결과 셀 클릭 → 드롭다운에서 PASS/FAIL/BLOCK/N/A/NS 선택 |
| ⌨️ 단축키 | 셀 선택 후 P(Pass), F(Fail), B(Block), N(NS) 키로 빠른 입력 |
| 📋 범위 채우기 | Ctrl+D로 현재 값을 아래로 복사, Shift+Click으로 범위 선택 |
| ↩️ Undo/Redo | Ctrl+Z로 실행 취소, Ctrl+Shift+Z로 재실행 (최대 200단계) |

Issue Link 칸에 주소(http/https)나 이슈 키를 적으면 옆에 ↗ 가 붙는다. 이슈 키는 설정 탭에 이슈 관리 도구 주소를 넣은 경우에만 붙는다. ↗ 는 해당 이슈를 새 탭으로 열고, 글자를 더블클릭하면 편집된다.

### 7-4. 첨부파일

- 결과 행에 이미지/문서 파일을 첨부할 수 있습니다.
- 지원 형식: 이미지(PNG, JPEG, GIF, BMP, WebP), 문서(PDF, DOC, XLSX, PPTX), ZIP, TXT, CSV, LOG
- 파일 크기 제한: **50MB**
- 이미지 파일은 미리보기가 제공됩니다.
- 드래그 앤 드롭으로 이미지를 첨부할 수도 있습니다.

### 7-5. 런 관리

| 기능 | 설명 |
|---|---|
| 완료 | 런 상태를 "완료"로 변경 |
| 다음 회차 | 같은 이름으로 다음 회차(최댓값 + 1) 생성. 버전 · 환경 · 시트 범위 · TC 를 이어받고 결과는 NS. 진행 중이면 먼저 완료 처리할지 물음 |
| 복제 | 기존 런을 "(복제)" 이름 · 같은 회차로 복제. 모든 결과가 NS로 초기화 |
| 삭제 | 런과 모든 결과, 첨부파일을 영구 삭제 |
| 내보내기 | 런 결과를 Excel 파일로 다운로드 |
| 결과 가져오기 | Playwright JSON 리포트나 JUnit XML 의 결과를 이 런에 기록 (진행 중인 런만, 7-6 참고) |

💡 **TIP**: 내장 타이머 기능으로 각 TC의 수행 시간을 기록할 수 있습니다.

### 7-6. 자동화 결과 가져오기

자동화 테스트 결과 파일을 올려 런 결과로 기록합니다. 테스트 제목 맨 앞의 TC ID 로 행을 찾습니다(예: `FE-AUTH-05 로그인 유지`).

1. 런 상단의 **결과 가져오기** 를 누르고 결과 파일을 고릅니다. Playwright JSON 리포트(`--reporter=json`)와 JUnit XML 을 받습니다.
2. **미리보기** 를 누르면 기록될 PASS · FAIL · NS 건수와 함께 test.fail 결함 재현 · 예상 밖 실패 · 결함 해소 후보 · 기존 결과 유지 · 런 범위 밖 · TC ID 를 찾지 못한 테스트 목록이 표시됩니다.
3. 확인한 뒤 **N건 적용** 을 누릅니다. 파일이나 옵션을 바꾸면 미리보기가 지워져 다시 미리보기를 거쳐야 합니다.

| 테스트 결과 | 기록 |
|---|---|
| 통과 | PASS |
| 실패 | FAIL (예상 밖 실패) |
| test.fail 결함이 그대로 재현 | FAIL |
| test.fail 인데 통과 | FAIL (결함 해소 후보, 수동 재확인) |
| 재시도에서 통과 | PASS (flaky 표시) |
| test.skip | NS (사유를 비고에) |
| 앞 테스트 실패로 미실행 | NS |

- 한 TC 를 여러 테스트가 덮으면 FAIL, NS, PASS 순으로 나쁜 쪽이 남습니다.
- 기본값으로 이미 기록된 결과는 NS 로 덮어쓰지 않습니다. 결과 · 실제 결과 · 비고는 덮어쓰고 이슈 링크는 그대로 둡니다.
- TC ID 는 제목 맨 앞이 프로젝트의 TC ID 와 정확히 같을 때만 매칭합니다. describe 제목의 ID 는 확인하지 않습니다.
- CI 에서는 수행을 미리 만들 필요가 없습니다. 저장소의 `scripts/ymtc-upload.mjs` 에 수행 이름만 주면 같은 이름의 다음 회차를 만들어 기록합니다(처음이면 R1). 버전 · 환경 · 시트 범위는 직전 회차를 이어받고, 주면 그 값으로 바뀝니다. `--round open` 은 진행 중인 회차에 이어 기록하고, `--dry-run` 은 회차를 만들지 않고 결과만 출력합니다.
- CLI 없이 직접 부를 때는 `POST /api/projects/{id}/testruns/import?run_name=...`(이름으로, 회차 자동 생성) 또는 `POST /api/projects/{id}/testruns/{run_id}/results/import`(기존 런에) 에 파일을 multipart 로 전송하고 API 키(4-1)로 인증합니다. `dry_run=true` 면 계산만 합니다.

```bash
# Playwright 실행 뒤 결과 올리기 (Node 18 이상)
PLAYWRIGHT_JSON_OUTPUT_NAME=results.json npx playwright test --reporter=list,json
YMTC_API_KEY=ymtc_... node scripts/ymtc-upload.mjs \
  --url http://127.0.0.1:8008 --project 1 --run-name "Starfort e2e" --version 1.6 results.json
```

⚠️ **JUnit XML 주의**: Playwright 의 junit 리포터는 `embedAnnotationsAsProperties: true` 를 켜야 test.fail 결함 재현이 FAIL 로 구분됩니다. 끄면 통과로 기록됩니다.

## 10. 리포트

> 📎 `16_report_tab.png`

테스트 런 결과를 요약 리포트로 확인하고, PDF/Excel로 다운로드할 수 있습니다.

1. 리포트 탭에서 테스트 런을 선택합니다.
2. 요약 섹션: 총 TC, 결과별 건수, PASS Rate(분모는 PASS+FAIL+BLOCK)를 확인합니다.
3. 수행 비교: 비교 대상은 기본이 같은 이름의 이전 회차이고 선택 목록에서 바꿀 수 있습니다. 카드 넷(이전 실패 TC · 수정된 TC · 미수정 TC · 퇴보 TC)과 변경 상세 표(TC ID · 우선순위 · 카테고리 · 변경 · 구분 · 연관 이슈)를 확인합니다.
4. 이슈: 제목과 링크로 이슈를 추가하거나 「이전 회차 이슈 가져오기」로 복사해 옵니다. 상태(해결 · 유지 · 부분 해결 · 미확인)를 찍으면 미해결 · 처리 완료 두 묶음으로 나뉘고, 연관 TC 가 모두 PASS 인 미확인 이슈에는 "해결 후보" 가 붙습니다.
5. 실패·차단 항목: FAIL 과 BLOCK 결과를 우선순위 높은 순으로, 실제 결과 · 이슈 링크와 함께 확인합니다.
6. 우선순위별 요약과 카테고리별 요약: 건수와 PASS Rate 를 확인합니다.
7. **PDF 다운로드**: 화면과 같은 차례의 리포트 파일(문구는 화면 언어). 파일 이름은 `프로젝트명_수행이름_Test_Report_날짜.pdf` (예: `Starfort_계정·세션정책_Test_Report_20260930.pdf`)
8. **Excel 다운로드**: Summary 시트(전체 현황, 수행 비교, 이슈, 우선순위별, 카테고리별 · 화면 언어)와 Results 시트(전체 결과)
